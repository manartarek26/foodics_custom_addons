4. Deferred: POS-side inventory

Confirmed gap, not yet fixed (per your call to add it later). Tracing core Odoo: a pos.order's stock.picking is only created by _process_saved_order() (the normal frontend flow) or, conditionally, inside action_pos_order_invoice() - and that condition only fires when the company's stock policy is "At the session closing" and anglo-saxon accounting is on (point_of_sale/models/pos_order.py, _should_create_picking_real_time()). foodics_accounting calls neither _process_saved_order() nor ever closes its session (by design - see _get_or_create_session()'s own docstring). Odoo's default company setting is "In real time" - under that default, no stock movement happens for a sale or a return, not only the return.

This affects both directions equally, so there is no accounting-vs-inventory split fix needed on the return side specifically - one fix covers both:

FileFix
foodics_accounting/models/foodics_pos_order.py, _create_via_pos_order() Call order._create_order_picking() right after action_pos_order_paid() succeeds.
foodics_accounting/models/foodics_pos_order.py, _create_via_pos_refund() Same call, same place - the negative-quantity lines already make core Odoo's _create_picking_from_pos_order_lines() produce a genuine return-direction picking (verified: it splits purely on quantity sign, no dependency on the native refund-linkage mechanism this module intentionally doesn't use).

Once that's in place, re-run full_cycle_testing_guide.html Case I end to end - it's already written to check On Hand at each step and will validate the fix immediately.
